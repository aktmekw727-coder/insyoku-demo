# 炭火酒場 よいどれ — 営業デモWebアプリ

飲食店オーナーにその場でスマホを渡して触ってもらうための「営業用デモ」です。
本番運用は想定しておらず、ログイン・DB・外部API接続は一切なし、すべてダミーデータと条件分岐だけで動作します。

## 1. 起動方法

ビルド不要の静的サイトです。好きな方法でローカルサーバーを立てて `index.html` を開くだけです。

```bash
# 例1: Pythonがあれば
python3 -m http.server 8000

# 例2: Node.jsがあれば (npxでhttp-serverを使う場合)
npx http-server -p 8000
```

ブラウザで `http://localhost:8000` にアクセスしてください。
スマホの実機で見せる場合は、同じWi-Fiに繋いだ端末から `http://<PCのIPアドレス>:8000` にアクセスするか、
Netlify / Vercel / GitHub Pages 等に `index.html` `style.css` `script.js` をそのままアップロードすれば公開できます（サーバーサイド処理は不要）。

ローカルの `index.html` を直接ダブルクリックして開くだけでも動作します。

## 2. ファイル構成

```
insyoku-demo/
├── index.html   … 全画面のHTML（1ページ内でセクション切り替え）
├── style.css    … デザイン（黒・濃い茶・生成り・金のシックな居酒屋テイスト）
├── script.js    … 画面切り替え・診断ロジック・ダミーデータ（全て条件分岐、API通信なし）
└── README.md    … このファイル
```

- 外部ライブラリ・フレームワークなし（素のHTML/CSS/JS）
- 外部通信・外部フォントなし（オフラインでも動作）
- ダミーデータ（メニュー・診断結果・ペアリング表など）は `script.js` の先頭にまとめてあるので変更が容易

## 3. 営業デモとして見せる順番（おすすめ）

1. **トップ画面** … 店名・キャッチコピー・6メニューを見せて「1つのアプリでここまでできる」感を出す
2. **あなたに合う一品診断**（デモの目玉） … 3問答えるとおすすめの料理×お酒が出る体験をオーナー自身にやってもらう。「これ、うちの店でもできるんですか？」を引き出す
3. **お酒とのペアリング** … 診断より軽い機能として、UIの作り込みやすさを見せる
4. **常連さん限定** … 「LINE登録者だけに配信」という一文で、来店促進・再来店施策の話につなげる
5. **クーポン** … その場でボタンを押して「クーポン獲得」演出を見せ、販促の即効性をアピール
6. **ご意見・口コミ** … 星評価で分岐する体験をさせ、「満足度の高い人だけ口コミに誘導する設計もできる」と説明
7. 最後にページ下部の「追加できる機能」エリア（予約管理・来店スタンプ・顧客管理など）を見せて、本格導入時の広がりを提示

## 4. 今後本番化する場合に必要な追加実装

- **データ管理**: メニュー・クーポン・診断ロジックを管理画面やスプレッドシート/DBから編集できるようにする（現状はコード直書き）
- **クーポン運用**: 発行済みクーポンの一意なコード発行・二重使用防止・スタッフ側の確認/消込機能
- **LINE/会員連携**: LINE公式アカウントやSMS配信との連携、会員登録・ログイン機能
- **口コミ導線**: 実際のGoogleビジネスプロフィールのレビューURLへの差し替え、口コミ投稿後のトラッキング
- **予約管理**: 予約受付・空席管理・リマインド通知
- **来店スタンプ／顧客管理**: 来店履歴・ポイント管理、顧客データの蓄積・分析（要DB・要ログイン）
- **アンケート／イベント告知**: 回答データの集計・管理画面
- **分析基盤**: どの診断結果が選ばれやすいか、クーポン利用率などのアクセス解析
- **セキュリティ・個人情報保護**: 会員情報を扱う場合はDB暗号化・プライバシーポリシー対応が必須
