# 焼肉 陣力 — 営業デモWebサイト（鹿児島県鹿屋市）

実店舗「焼肉 陣力」をベースにした営業用デモWebサイトです。
本番運用は想定しておらず、ログイン・DB・外部API接続は一切なし、すべてダミーデータと条件分岐だけで動作します。

デザインは白・生成り・木目をベースに、黒とえんじ（深い赤）をアクセント、金は見出し・ロゴなど最小限に留め、
「明るく清潔感があり、家族・子供連れでも入りやすい地元の焼肉店」という実店舗の雰囲気を大切にしています。

## 1. 起動方法

ビルド不要の静的サイトです。好きな方法でローカルサーバーを立てて `index.html` を開くだけです。

```bash
# 例1: Pythonがあれば
python3 -m http.server 8000

# 例2: Node.jsがあれば (npxでhttp-serverを使う場合)
npx http-server -p 8000
```

ブラウザで `http://localhost:8000` にアクセスしてください。
ローカルの `index.html` を直接ダブルクリックして開くだけでも動作します。

### GitHub Pagesで公開する場合

1. このリポジトリの Settings → Pages で、公開したいブランチ（例: `main` またはこの作業ブランチ）と `/`（ルート）を指定
2. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される
3. サーバーサイド処理は無いため、`index.html` / `style.css` / `script.js` / `assets/` をそのまま置くだけでOK

## 2. ファイル構成

```
insyoku-demo/
├── index.html          … 全ページ（ヘッダー・ヒーロー・メニュー・診断・店舗情報など）
├── style.css           … デザイン（白・生成り・木目＋黒・えんじのアクセント、金は最小限）
├── script.js           … カテゴリ/メニュータブ/診断ロジック/ダミーデータ（すべて条件分岐、API通信なし）
├── assets/images/      … 差し替え用の写真を置くフォルダ（README.md に一覧あり）
└── README.md           … このファイル
```

- 外部ライブラリ・フレームワークなし（素のHTML/CSS/JS）
- 外部通信・外部フォントなし（オフラインでも動作、GitHub Pagesにそのまま置ける）
- ダミーデータ（メニュー・おすすめ・診断ロジックなど）は `script.js` の先頭にまとめてあるので変更が容易
- 写真が無い箇所は木目調のプレースホルダー（キャプション付き）が表示され、レイアウトは崩れない

## 3. 営業デモとして見せる順番（おすすめ）

1. **ホーム（ヒーロー）** … 「鹿屋で、家族と。仲間と。今日もおいしい焼肉を。」というコピーと5つのメニューカテゴリで、店の雰囲気とWebサイトの完成度を見せる
2. **メニュー（タブ切替）** … カルビ・ロース・タン・ホルモン・セットなど15カテゴリをタブで切り替えられることを見せ、「紙メニューが全部Webで見られる」体験を伝える
3. **おすすめ** … 陣力カルビ・特選カルビ・ファミリーセットなど人気メニューを写真付きカードで紹介
4. **何を頼めばいい？診断**（デモの目玉） … 人数・気分・予算の3問に答えると「家族4人ならファミリーセット＋上タン塩＋お子様メニュー」のようにおすすめの組み合わせが提案される。オーナー自身に触ってもらい「これ、うちの店でもできるんですか？」を引き出す
5. **店舗情報** … 店内紹介・クーポン・アクセス・お子様/家族利用の訴求・LINE導線・ご意見（口コミ）をひとつずつ見せる
6. 最後にフッターの「追加できる機能」エリア（予約管理・来店スタンプ・顧客管理など）を見せて、本格導入時の広がりを提示

## 5. 今後本番化する場合に必要な追加実装

- **データ管理**: メニュー・価格・診断ロジックを管理画面やスプレッドシート/DBから編集できるようにする（現状はコード直書き）
- **予約管理**: 予約受付・空席管理・リマインド通知（現状は電話番号リンクのみ）
- **クーポン運用**: 発行済みクーポンの一意なコード発行・二重使用防止・スタッフ側の確認/消込機能
- **LINE連携**: LINE公式アカウントとの実連携、クーポン配信・来店促進メッセージ
- **来店スタンプ／顧客管理**: 来店履歴・ポイント管理、顧客データの蓄積・分析（要DB・要ログイン）
- **アンケート／イベント告知**: 回答データの集計・管理画面
- **実際の地図・アクセス情報**: Googleマップ埋め込み、実際の住所・電話番号への差し替え
- **分析基盤**: どの診断結果が選ばれやすいか、クーポン利用率などのアクセス解析
- **セキュリティ・個人情報保護**: 会員情報を扱う場合はDB暗号化・プライバシーポリシー対応が必須
